# alaio-web-lab

Рабочая лаборатория веб-дизайна Alaio: реальные секции SaaS-лендингов, разбираемые из Figma и фиксируемые здесь как правила.

## Структура документации

- [docs/design-system.md](docs/design-system.md) — точка входа: назначение, ссылки на разделы, каталоги блоков и компонентов, ссылка на открытые вопросы.
- [docs/foundations/](docs/foundations/README.md) — общие правила бренда (визуальные принципы, цвета, типографика, сетка/отступы, радиусы, иконки, источники и токены). Один файл — одна тема.
- [docs/components/](docs/components/README.md) — переиспользуемые компоненты (кнопки, чип, вкладки меню, пункт FAQ, заголовочная группа). Один файл — один компонент; цветовые/контекстные варианты компонента — внутри его файла.
- [docs/blocks/](docs/blocks/README.md) — готовые блоки страницы, собранные из компонентов и основ. Один файл — один блок; цветовые/контекстные варианты блока — внутри его файла.
- [docs/design-system-open-questions.md](docs/design-system-open-questions.md) — противоречия, незавершённый перенос из Figma, вопросы без решения.

## Как добавлять новый элемент

Постоянная структура роста — тип элемента определяет, куда он попадает:

| Тип элемента | Куда добавлять |
|---|---|
| Общее правило бренда (не привязано к одному компоненту/блоку) | Новый или существующий файл в `docs/foundations/` |
| Компонент (переиспользуемый элемент интерфейса) | Новый файл в `docs/components/` |
| Блок (готовая секция страницы) | Новый файл в `docs/blocks/` |
| Цветовой/контекстный вариант существующего компонента или блока | Внутри спецификации его собственного файла, не отдельным файлом |

Шаги:

1. Проверить существующие спецификации в `docs/foundations/`, `docs/components/`, `docs/blocks/` — если подходящий файл уже есть, обновлять его, а не создавать дубликат.
2. Определить тип элемента по таблице выше и создать файл в соответствующей директории по единому формату страницы (см. [docs/design-system.md](docs/design-system.md) → любую страницу компонента/блока как образец: назначение, источник и статус, структура, геометрия, типографика, цвета и варианты, состояния и поведение, адаптивность, правила контента, связанные компоненты и токены, проверка).
3. Добавить ссылку на новый файл в оглавление соответствующего раздела (`docs/foundations/README.md`, `docs/components/README.md` или `docs/blocks/README.md`) и в каталог на `docs/design-system.md`.
4. Работа с токенами и статусом значений (что считать согласованным правилом, когда писать «Не задано») — по соглашению из [docs/foundations/sources-tokens.md](docs/foundations/sources-tokens.md), не дублировать его здесь.
5. Если обнаружено противоречие с уже задокументированным правилом — не выбирать значение молча, фиксировать оба источника в [docs/design-system-open-questions.md](docs/design-system-open-questions.md).

## Названия блоков

Названия блоков в каталоге, заголовках спецификаций и Figma — на английском. Использовать одинаковое название из каталога `docs/blocks/README.md`. Вариант или состояние в имени Figma указывать после `/`, также на английском (например, `Top Menu Slider / Light Gray`, `Metaball Sidebar Slider / Active Item 2`). Тексты правил могут оставаться на русском.
